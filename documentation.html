🗜️ Context Compression & Low-VRAM Token Economy

app/context-engine.ts

How does a 3B model reason across a 10,000-line repository? The agent uses progressive, loss-free token reduction:

AST Signature Extraction (extract_symbols)

Strips internal method implementations, leaving only function signatures, interfaces, classes, and exported types. Reduces a 2,000-line file into 80 tokens (up to 95% token savings) while preserving full structural comprehension.

Focused Window Slicing (context_extract)

Instead of reading entire files into prompt memory, the agent slices a surgical window (e.g. 15 lines radius) around target symbols, functions, or line numbers.

Git Diff Digesting (summarize_diff)

Compresses uncommitted working tree modifications into concise functional changelogs before passing them to the model for review or commit message generation.

Dynamic History Rolling (compress_history)

When conversation turns approach context limits, the history is digested into an executive summary, preserving the active causal dependency graph without forgetting prior decisions.

📦 Progressive Tool Discovery vs Schema Bloat

app/tool-discovery.ts

Traditional agents inject 40+ tool JSON schemas into every prompt payload, consuming 3,000–5,000 tokens before the model even reads the user query. This assistant solves schema bloat via Progressive On-Demand Discovery:

1. Lean Core Baseline

The agent initializes with only fundamental primitives in its schema: Read, Write, Edit, Glob, Grep, Bash, ToolsAvailable, and ToolSearch.

2. Just-In-Time Expansion

When specialized capabilities are needed (e.g. Database queries, AST refactoring, LSP definition jumps), the model invokes ToolSearch("database") to dynamically load schemas on the fly.

💡 Frequently Asked Questions & Scenarios

Developer Q&A
🏛️ Architecture FAQ · 01

Connector vs Plugin vs Tool vs Hook — What's the difference?

Tool
A discrete function directly invoked by the model (e.g. Read, Edit, Tree, Grep).
MCP Tool
An external tool hosted over Model Context Protocol JSON-RPC via .agents/mcp.json.
Connector
Persistent infrastructure bridge (PostgreSQL, MySQL, SQLite, GitHub) managing pools, health, and latency.
Hook / MW
Lifecycle interceptors executing before/after turns without consuming LLM token context.
Plugin
A packaged distribution bundle uniting skills, behavioral rules, and specialized tools into one module.
⚡ Database Optimization FAQ · 02

How can a 3B model query 50,000 DB rows without choking?

The agent enforces Database-Side Computation: heavy filtering and aggregations are delegated to the underlying SQL engine rather than loading raw row objects into LLM context memory.

50,000 Rows Database Storage
➔
SQL Engine SUM · COUNT · GROUP
➔
5ms Query Zero Host Latency
➔
1–5 Rows Prompt Context (~0.1%)

By issuing analytical queries through read_query, millions of bytes are crunched in milliseconds inside PostgreSQL/SQLite. The model receives only clean, high-signal statistical summaries.

🔍 PostgreSQL Engine FAQ · 03

Why did reltuples say 0 rows and how does Tiered Counting fix it?

In PostgreSQL, pg_class.reltuples is an un-vacuumed statistical estimate. When a table has freshly inserted rows that haven't been vacuumed or analyzed, reltuples often falsely reports 0.

⚡ Tier 1: Fast reltuples
Instant catalog estimate (<1ms). Ideal for million-row tables to prevent costly table-level locks.
🛡️ Tier 2: Safe COUNT(*)
If reltuples reports 0, falls back to exact count protected by statement_timeout = 500ms.

This dual-tier approach guarantees pinpoint accuracy for active development tables while ensuring large production tables never cause connection stalls.
